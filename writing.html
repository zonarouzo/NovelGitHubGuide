原稿の流れ

テンプレートでは、原稿は次の順番で育てていきます。

段階置き場所（本編の場合）形式
① プロットnovels/plots/.md
② 第一稿・書きかけnovels/drafts/.txt
③ 完成原稿novels/ の直下.txt

🛡 テンプレートのルール（CLAUDE.md）で守られていること

  • 完成原稿は、あなたがはっきり指示しない限り変更されません
  • 原稿の削除は、あなたの許可が必要です
  • 第一稿を完成原稿にするのも、あなたの指示があったときだけです
  • 共通設定とスピンオフの設定が食い違っていたら、Claude はあなたに確認します
  • Claude は、既存の原稿や設定を読んでから執筆します

プロンプトの【 】の部分は、自分の内容に書き換えて使ってください。

プロットの作成・保存

各話のあらすじや展開をまとめた「プロット」を作ります。Claude はこれまでの原稿や設定を読んでから作り、plots/ フォルダに保存します。

まずは案を出してもらってから選びたい場合は、こちらが便利です。

第一稿の執筆

プロットをもとに、第一稿を書いてもらいます。第一稿は drafts/ フォルダに保存されます。

✍️ 自分で書いた原稿を入れたいとき

自分で書いた文章を Claude Code の入力欄に貼り付けて、「これを第◯話の第一稿として保存して」と頼むこともできます。

第一稿の修正

直してほしいところを、できるだけ具体的に伝えます。

直す前に意見だけほしいときは、「ファイルは変更しないで」と書き添えます。

完成原稿としての保存

第一稿が仕上がったら、完成原稿にします。「完成原稿にして」とはっきり伝えたときだけ、Claude は第一稿を完成原稿の場所に移します。

完成原稿をあとから直したいときは、「完成原稿の」と明記して頼みます。

キャラクター設定の追加・変更

キャラクターの設定は settings/characters.md などにまとめて保存されます。

世界観設定の管理

舞台・歴史・ルールなどの世界観は settings/ フォルダの資料にまとめます。原稿に出てきた新しい設定を、資料に反映してもらうこともできます。

設定と原稿の食い違いが気になったら、矛盾チェックを頼みましょう。

文体の管理

Claude は、settings/style_guide.md（文体・表記のルール）と、settings/style_samples/（あなたの過去作などの文体サンプル）を読んでから執筆します。文体サンプルはあとから何本でも追加できます。

スピンオフの作成・管理

スピンオフは spinoffs/ フォルダの中に、作品ごとのフォルダを作って管理します。共通の設定は本編と共有し、そのスピンオフだけの設定は専用の settings/ に保存します。

過去の原稿の確認・復元

GitHub には、保存のたびに変更の履歴が残ります。

Claude に頼む

GitHub の画面で見る

  1. GitHub で自分の小説リポジトリを開き、見たいファイル（例：novels/episode01.txt）をクリックします。

  2. ファイルの上のほうにある History（履歴）をクリックすると、変更の一覧が表示されます。

  3. 一覧の項目をクリックすると、そのときに何が変わったかを確認できます。

履歴に残るのは、GitHub に保存（反映）された変更です。

作業内容の保存と反映

🛠 自動で main に反映する仕組みは準備中です

Claude の作業内容を、利用者の操作なしで「main（メインの保存場所）」に反映する仕組みを準備していますが、まだ検証が終わっていません。現時点では、下の暫定の手順で反映してください。

今の保存のしくみ

ブラウザ版の Claude Code は、作業が終わると、変更内容を GitHub に保存します。ただし保存先は、多くの場合 main ではなく、その作業専用の「ブランチ（作業用の保存場所）」です。

そのままにしておくと、main の原稿は古いままです。次に新しい会話を始めたとき、Claude が前回の作業内容を見られないことがあります。

暫定の手順：作業内容を main に反映する

  1. Claude の作業が終わったら、Claude Code の画面に表示される変更内容の欄で Create PR をクリックします。

  2. 「プルリクエスト（PR）」という「変更を main に取り込むための申請」が GitHub に作られます。表示されたリンクから、GitHub のページを開きます。

  3. GitHub のページで、内容を確認し、Merge pull request をクリックします。

  4. Confirm merge をクリックします。これで作業内容が main に反映されます。

ℹ️ 保存できたか不安なときは

Claude に次のように聞くと、今の状態を説明してもらえます。

ブランチやプルリクエストについては よくある質問 でも説明しています。

このページのまとめ

  • プロット → 第一稿 → 完成原稿 の流れで執筆する
  • 設定資料やスピンオフも Claude に頼んで管理できる
  • 作業が終わったら、main への反映を忘れずに（現在は暫定の手順）

ほかの指示の例は プロンプト集 にまとめています。
